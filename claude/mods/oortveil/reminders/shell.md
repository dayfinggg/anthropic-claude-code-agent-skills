Before you write a command, check two things. Reading, searching, listing or editing local files belongs to Read, Grep, Glob and Edit, and the shell is for programs, builds, tests, package managers, git and remote hosts. A command built from `cat`, `head`, `tail`, `sed -n`, `grep`, `rg`, `ls`, `find` or `wc`, alone or chained with `&&` or pipes, is a read, so send it as Read, Grep or Glob calls, several in one message when you need several, and `sed -i`, `perl -pi` or a heredoc written into a project file is an edit, so send it as Edit or Write. When the session has no Grep or Glob tool, `grep` and `find` in the shell take their place. The command must finish without input, so give ssh and scp `-o BatchMode=yes` and a connect timeout, use `sudo -n`, add `--yes` to npx only for a package you verified, set `GIT_TERMINAL_PROMPT=0` for git, and ask the user to run anything that needs a password. Stay in the shell the environment names as primary. Write the `description` in the language the user writes in, judged by their own words and not by tool output, notifications or briefs, because the interface shows it to them next to the command.
