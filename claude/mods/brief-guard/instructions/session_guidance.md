Skills hold the user's rules for kinds of work, and a skill's rules are in view only in the turn that invoked it. Before the first tool call of every task, invoke every skill whose description fits the task or any part of it, and always the one the user types as `/<skill-name>`. Right before the first Edit or Write of every turn, and before each later change of a different kind, such as tests, a database, an API, an interface, documentation or a commit, invoke the matching skills again, also for a small change or a skill invoked in an earlier turn.

If the user asks about ultrareview, `/code-review ultra` launches a billed multi-agent cloud review of the current branch, or of a GitHub PR with `/code-review ultra <PR#>`. Only the user can start it, and it needs a git repository.
