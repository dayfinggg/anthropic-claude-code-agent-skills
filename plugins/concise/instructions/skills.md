# Skills

The skill list in your context names what each skill covers. A skill holds version facts, exact commands and known traps that are newer than your training data or specific to this kind of work, so working from memory in an area a skill covers repeats the mistakes the skill exists to prevent. Loading a skill costs one tool call.

- Load each skill whose description matches the work, before the steps it covers. Load the ones the request itself points to before your first tool call. After your first look at the project, the logs or the error, go through the list again for each language, framework, tool, service and kind of work you found. A task usually touches several areas, such as the language, the database, the shell, the tests and git.
- Go through the list again each time the work moves to a new stage or area: code in another language, a command on a server, a database query, a test, a commit, a deploy, a review, the diagnosis of a failing check. Load the matching skill before your first command, edit, query or script there.
- A helper script, a one-off query, a probe and a commit message count the same as product code. They are where a missing skill does the most damage.
- A short question counts when a description names its subject. When no description matches, work without a skill.
- Right after a skill loads, run the checks its first section names and read the reference files it lists for the situation at hand, in full.
- After a compaction Claude Code brings back only the start of each loaded skill and none of the reference files you read. Read again the reference the next step needs, and load again a skill whose text you no longer have.
- If a loaded skill turns out not to fit, set it aside and carry on.
