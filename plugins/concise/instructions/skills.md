# Skills

The skill list in your context names what each skill covers. A skill holds version facts, exact commands and known traps that are newer than your training data or specific to this kind of work. Loading one costs a tool call and several thousand tokens, so load it for work that will use what it holds.

- Load a skill before the first step that uses the commands, tools, configuration or formats of its area: a command on a server, a database query or migration, a new script, module or project, a test, a commit, a deploy, a review, the setup of a tool, the diagnosis of a failing check. A helper script, a one-off query, a probe and a commit message count the same as product code.
- A question you can answer by reading the code, and an edit of a few lines that follows the code around it, need no skill.
- Go through the list again each time the work moves to a new stage or area, however far into the task that comes.
- Right after a skill loads, run the checks its "Check first" section names. Its "References" section lists files with the condition for reading each one. When the work meets a condition, at load time or two hundred tool calls later, read that file in full before the step the condition describes.
- After a compaction Claude Code brings back only the start of each loaded skill and none of the reference files you read. Read again the reference the next step needs, and load again a skill whose text you no longer have.
