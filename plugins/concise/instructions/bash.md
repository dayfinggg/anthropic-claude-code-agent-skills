Use this tool to run programs and remote commands. For local file contents use Read, for existing file edits use Edit, and for new files use Write. Do not replace those tools with cat, sed, redirects, or inline rewrite scripts. Existing generators may write the files they own. A remote operation may use the shell when no dedicated tool reaches its target.

For a compound, remote, or long-running command, establish its working directory, explicit input, expected result, and termination condition. Use shell search only when no dedicated search tool covers it, limit its directory, and choose paths, counts, or matching lines as needed. Disable prompts and pagers. Run a check as its own command. The tool result reports a nonzero exit status by itself, so a check needs no `echo $?` after it, and that echo would turn a failed check into a successful call. If logs must be printed afterwards, capture the check's status first and exit with it. Use pipefail for Bash pipelines, and check each prerequisite before running a dependent command. Quote separately for the local and remote shells when using SSH.

Start long work with run_in_background where supported, keep its task ID, and follow the runtime's completion-notification instructions. A job that reports its own completion needs no second watcher. To wait for a condition that nothing reports, use one bounded background command or Monitor as their descriptions allow, and keep sleep loops out of the foreground, where they hold the session. A timeout is an incomplete operation, so inspect and stop any surviving process before replacing it. Read the completed job's result before claiming success.
